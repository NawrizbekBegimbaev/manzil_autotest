# Manzil — воспроизведение блокирующих багов (для разработки)

Окружение: **staging** (`https://staging-manzil.greatmall.uz`).
Приложение склада: `uz.logos.manzil.warehouse.staging` **1.1.1-staging** (versionCode 3).
Учётки — в `.env` проекта автотестов (super_admin) и создаются прогоном (грузоотправитель/склад).

## BUG-011 (P1) — оператор склада не может добавить адрес заявки (приложение)

**Где:** мобильное приложение склада → создание заявки → адрес.
**Предусловие:** установлено приложение склада, есть аккаунт «Сотрудник склада».

**Шаги:**
1. Войти в приложение склада (телефон + пароль → «Kirish»).
2. Нажать «Ariza yaratish» (создать заявку).
3. Выбрать «Avtomobil» → тип машины «BIG 800» → «1 haydovchi».
4. Нажать поле «Yuklash manzili» (адрес отправления) → «Manzil qoʻshish».
5. Заполнить «Shahar» (город), «Davlat» (страна), «Tuman / manzil» (район) — свободным текстом.
6. Нажать «Qoʻshish».

**Ожидаемо:** адрес добавлен и показан в маршруте; можно продолжить и опубликовать заявку.
**Фактически:** тост **«Noto'g'ri so'rov»** (400), адрес не добавляется. Опубликовать заявку невозможно.

**Доказательство (лог OkHttp с устройства):**
`POST /api/v1/warehouse/locations` — тело ~58 байт (без `cityId`) → **400 BAD_REQUEST**.
Проверка контракта напрямую по API:
- `{"name","cityName":"Beijing","country":"China","address"}` → **400**
- `{"name","cityId":"<uuid>","address"}` → **201** ✅

**Причина:** приложение шлёт свободный `cityName+country`; бэкенд принимает адрес только по `cityId`
(в приложении нет выбора города из справочника). Нужен новый билд с city-picker'ом.

## BUG-012 (P1) — оператор склада не может отметить связь с водителем (приложение)

**Где:** приложение склада → заявка «В работе» (Ishda) → связь.
**Предусловие:** заявка в статусе «В работе» с назначенным водителем.

**Шаги:**
1. Войти в приложение склада → вкладка «Ishda».
2. Открыть заявку → секция «Haydovchi bilan aloqa».
3. Нажать «Ha, gaplashdik» (да, связались).

**Ожидаемо:** статус связи → «связались»; становится активной кнопка «Yuk joʻnatildi» (отправить груз).
**Фактически:** тост **«Noto'g'ri so'rov»** (400); статус остаётся «Aloqa talab qilinadi»; отправка груза недоступна.

**Доказательство:** `POST /api/v1/warehouse/orders/{id}/communication` — тело ~16 байт (напр. `{"status":"YES"}`)
→ **400**. Рабочий контракт: `{"status":"CONFIRMED"}` (или `NOT_REACHED`).

## BUG-013 (P1) — выбор города сломан в веб-UI грузоотправителя/супер-админа

### 13a. Нет добавления города (супер-админ)
**Шаги:** войти как super_admin → меню «Города» (`/super-admin/cities`).
**Ожидаемо:** есть кнопка «Добавить» для нового города.
**Фактически:** кнопки нет — страница стала справочником-просмотром (фильтр Страна/Уровень/Путь + таблица).

### 13b. Пустой дропдаун «Город» в форме склада (грузоотправитель)
**Шаги:**
1. Войти как admin грузоотправителя.
2. «Логистика» → «Склады» → «Добавить склад».
3. В диалоге выбрать «Страна» → **China**.
4. Открыть дропдаун «Город».

**Ожидаемо:** список городов China (Beijing, Guangzhou, Shanghai, …).
**Фактически:** дропдаун **пустой** (0 вариантов), хотя подсказка «Сначала выберите страну» уже пропала.

**Доказательство:** данные есть — `GET /api/v1/cities?countryId=<China>` → **200** возвращает 7 городов
(Beijing, Khorgos, Guangzhou, Urumqi, Shanghai, Ulug'chat, Yiwu). То есть фронт формы склада их не подтягивает.
Без выбора города склад создать нельзя → блокирует и добавление, и удаление склада.

## BUG-014 (P2) — действия жизненного цикла заказа отсутствуют в веб-UI

**Где:** карточка заказа (грузоотправитель `/shipper/orders/{id}`, оператор `/shipper/storeroom/{id}`)
и раздел «Диспетчер» (`/shipper/communication`).

### 14a. Нет отмены заказа (admin)
**Шаги:** admin → «Список заказов» → открыть заказ в статусе «Выбран ТК».
**Ожидаемо:** доступна кнопка «Отменить заказ».
**Фактически:** на карточке только «Назад», номер, степпер статусов, инфо о заказе/транспорте, список
предложений, журнал операций — **ни одной кнопки-действия**.

### 14b. Нет связи с водителем (менеджер/диспетчер)
**Шаги:** менеджер → «Диспетчер» → строка заявки «В работе».
**Ожидаемо:** действие «Связь с водителем» (отметить дозвон).
**Фактически:** у строки нет действий; на карточке заявки — только инфо, без кнопок.

### 14c. Нет отмены/повторной публикации (менеджер, «Оператор»)
**Шаги:** менеджер → «Оператор» → открыть заявку.
**Ожидаемо:** «Отменить» и (для отменённой) «Опубликовать повторно».
**Фактически:** кнопок нет.

**Итог по 014:** действия над заказом были доступны до редизайна (через ⋮-меню/кнопки), сейчас на
переработанных страницах отсутствуют. Нужно вернуть/локализовать действия в новом UI.
