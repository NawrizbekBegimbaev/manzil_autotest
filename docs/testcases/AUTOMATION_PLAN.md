# Автоматизация UAT-чеклиста (74 кейса) — план

Цель: покрыть автотестами все 74 кейса из `manzil-uat-checklist.xlsx`
(Super admin 18, Admin 19, Сотрудник Склада 14, Менеджер 9, TK 14).

## Архитектура
- **Web** (SA/AD/MN/TK): Playwright (sync) + pytest + Page Object Model. Поверх
  существующего каркаса (`conftest.py` self-provisioning, `pages/*`).
- **Mobile** (SK): Maestro на Android-эмуляторе (`mobile/flows/*`).
- **Роли создаёт прогон** (`cast`-фикстура на базе `provisioned`): super_admin (из .env)
  → грузоотправитель + его admin → трак-компания + её TK → менеджер → сотрудник склада.
- **Предусловия-заказы** — через **API-seed** (`utils/api_seed.py`, httpx): логин
  складского аккаунта (clientType=WAREHOUSE_APP) → `POST /warehouse/orders`; для статусов
  QUOTED/SELECTED — оффер TK и выбор админом. Setup через API, проверки — в UI.
- **Маппинг:** каждый тест = `@allure.title("<UAT-ID> …")` + маркер роли
  (`super_admin`/`admin`/`manager`/`tk`/`warehouse`). Скрипт `scripts/sync_results.py`
  проставляет Passed/Failed в колонку QA чеклиста по ID.
- **Очистка:** все созданные сущности — с префиксом `SANITY`, teardown удаляет арендаторов.

## Волны реализации
1. **Wave 1 — Super admin (SA-01..18):** самодостаточно (нужен только super_admin).
   POM: компании (есть), + водители, города, типы транспорта; методы list/search/edit/delete/block.
2. **Wave 2 — Admin (AD-01..18):** дашборд, заказы (+seed), отклики, выбор победителя,
   сотрудники, склады, отчёты, отмена/завершение.
3. **Wave 3 — Менеджер (MN-01..08):** оператор склада, диспетчер, связь, отмена/republish.
4. **Wave 4 — TK (TK-01..14):** лента, оффер, мои предложения, водители, назначение, старт.
5. **Wave 5 — Сотрудник склада (SK-01..13):** Maestro (эмулятор) — вход, список,
   создание заявки и публикация, связь, отправка груза.
