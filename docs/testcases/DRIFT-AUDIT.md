## 🧩 Находка про capability-гейтинг (уточнено проверкой)

Изначально казалось, что capability-гейтинг сломан системно. **Проверка показала: бэкенд
гейтит по capability КОРРЕКТНО** (`ORDER_ENTRY`, `SMS_BLAST` — enforced, гранты работают).

Реально сломан **только фронт для `SEE_PRICES`** — точечный баг, не система:

| ID | Capability | Статус |
|---|---|---|
| WEB-SHP-030 | `SEE_PRICES` | 🔴 **БАГ** — фронт гейтит `role===ADMIN`, игнорирует грант; менеджер с `SEE_PRICES` цену не видит |
| API-AUTH-075 | `ORDER_ENTRY` | ✅ enforced на бэкенде (OPERATOR c грантом создаёт заказ) — не баг |
| API-INT-068 | `SMS_BLAST` | ✅ enforced на бэкенде (без гранта 403, с грантом 2xx) — не баг |
| WEB-SHP-051 | `SMS_BLAST` | 🔴 minor — UI показывает кнопку SMS без проверки гранта (бэкенд 403 защитит; UX-протечка) |

**Рекомендация:** починить фронт `SEE_PRICES` (WEB-SHP-030) — гейтить по capability, а не по
роли, по образцу того, как это уже корректно сделано на бэкенде.
