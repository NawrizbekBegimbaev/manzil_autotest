# Manzil — Тест-кейсы

`manzil-testcases.xlsx` — воркбук тест-кейсов в формате MyXodim/BusinessHub:
сводный лист **Сводка** + по листу на раздел.

Колонки каждого листа: `ID | Раздел | Экран / Подраздел | Сценарий | Предусловия |
Шаги | Ожидаемый результат | Приоритет | Статус | Комментарий`.

Источник истины — JSON в `data/` (по файлу на раздел), редактируется руками или
скриптами; затем воркбук пересобирается:

```bash
.venv/bin/python scripts/build_testcases_xlsx.py
```

Импорт в Google Sheets: Файл → Импорт → загрузить `manzil-testcases.xlsx`.

## Состав (384 кейса)

| Лист | Раздел | Кейсов |
|---|---|---|
| Аутентификация | Логин/refresh/logout, /me, clientType | 45 |
| RBAC | Матрица ролей, 401/403/404, blocked, wrong-app | 28 |
| SA — Компании | SUPER_ADMIN: грузоотправители, трак-компании | 38 |
| SA — Водители+Справочники | SUPER_ADMIN: водители, города, типы ТС | 35 |
| Грузоотправитель | Заказы, сотрудники, склады, отчёты, дашборд | 73 |
| Перевозчик+Тендер | Лента, офферы, водители, назначение, старт, выбор победителя | 77 |
| Мобайл | Warehouse-app, Carrier-app | 41 |
| Интеграции+E2E | 1C webhook, уведомления, устройства, файлы, сквозной тендер | 47 |

`Комментарий` помечает уровень: `api` / `web` / `mobile` / `e2e` / `negative` / `validation` / `boundary` / `wrong-app`.
`DRIFT` в ожидаемом результате = расхождение код↔доки (см. `docs/PROJECT_REFERENCE.md` §12).
Колонка `Статус` пустая — заполняется при прогоне (passed/failed/blocked).

Основа кейсов — `docs/PROJECT_REFERENCE.md` (полная модель продукта).
