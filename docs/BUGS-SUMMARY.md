## Группировки для передачи (чинить пачками дешевле)

### Пакет 1 — «Один паттерн, одна правка»: гонки state-transition
- **BUG-035 (MNZL-275)** — 4 поверхности (cancel / enter-1c / goods-sent / 1С-webhook) дают 500 вместо 409;
  корень один — нет единой блокировки/optimistic-guard на переход статуса заказа. Одна правка (лок на
  агрегат заказа + маппинг конфликта в 409) закрывает все 4.
- **BUG-038 (MNZL-280)** — тот же класс concurrency-инварианта на прикреплении водителя (двойное
  назначение). Логично чинить в том же заходе тем же механизмом сериализации.

### Пакет 2 — i18n / нелокализованные справочники и сообщения (крупнейший кластер)
Общий корень: **серверные/справочные значения и системные сообщения не проходят через локализацию.**
- **BUG-037 (MNZL-279)** — carrier: имя `vehicleType` приходит по-китайски (`平板 13.7`), в складском — латиница (`Bortli 13.7`).
- **BUG-041** — web: пикер стран (англ.+ISO+код), страница 404 (англ.).
- **BUG-028** — warehouse: ошибки входа на английском.
- **BUG-032** — carrier: уведомления на китайском.
- **BUG-034** — carrier: диалоги на узбекском при русском UI.
- **BUG-029** — carrier: технические ошибки (wrong-app/лимит) не имеют локализованного текста → «Непредвиденная ошибка».

### Пакет 3 — контракт ошибок / коды статусов
- **BUG-039** — пустой `q=""` → 500 вместо 400 (валидация до запроса).
- **BUG-036 (MNZL-276)** — унифицировать стратегию сокрытия кросс-тенантных ресурсов (403 vs 404).

### Пакет 4 — достижимость интеграций
- **BUG-040** — вебхук 1С за Keycloak-JWT; 1С аутентифицируется shared-secret → эндпойнт недостижим. Нужен путь аутентификации по секрету для батч-вебхука.

### Пакет 5 — мобильный UX (диагностировано клиентским; ре-верификация в Фазе 4)
- **BUG-030 / BUG-031 / BUG-033** — сообщения назначения, список замены водителя, подтверждение выхода.
  Диагностированы как клиентские дефекты приложения перевозчика на staging 2026-07-23; при написании
  мобильного слоя (Фаза 4) — ре-верифицировать текущее поведение флоу и держать «правильный» assert рядом.
